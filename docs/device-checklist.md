# 實機驗證清單

這些是**只有在真實裝置上才驗證得了**的東西。目前為止所有測試（單元 43、整合 15）
都跑在 Node 環境，SQLite 那條路徑與相機從來沒有被真正執行過。

## 安裝

1. 手機下載 APK（preview 版，獨立運作，不需要電腦）
2. Android 會擋「未知來源」→ 允許安裝
3. 第一次開啟需要網路（要建立匿名帳號）

## A. 離線寫入 —— 最關鍵的一項

`outbox.ts` 與本地 SQLite 至今一行都沒在真機上跑過。

1. 正常連線下建立群組、加一個成員
2. **開飛航模式**
3. 新增 3 筆支出、編輯其中 1 筆、刪除 1 筆
   - 預期：畫面立刻反應，完全不卡頓，沒有錯誤
4. 關掉飛航模式，等幾秒
5. 用網頁版（https://gugugagasplit.expo.app）以同一身分登入查看
   - 預期：3 筆新增、1 筆編輯、1 筆刪除都同步過去，**數量完全一致**

### A2. 重複開關網路（冪等性）

同步進行中反覆開關飛航模式 3–5 次。

- 預期：**不會出現重複資料**。這是 outbox 用固定 UUID + upsert 的重點，
  在 Node 測過協定層，但沒在真的斷線情境下驗證過。

## B. 收據照片

`expo-image-manipulator` 的壓縮與檔案搬移都只在型別層檢查過。

1. 新增支出 → 拍收據 → 允許相機權限
2. 預期：縮圖立刻出現，標示「待上傳」
3. 稍等後重整，預期：「待上傳」消失（已上傳完成）
4. **離線拍一張**：飛航模式下拍照 → 縮圖要照樣出現且標「待上傳」
   → 恢復連線後自動送出

## C. 多幣別與結算

1. 記一筆 JPY、一筆 TWD
2. 結餘頁預期：兩個幣別**分開顯示**，不會被換算合併
3. 結算 → 選跨幣別還款 → 自己填匯率
   - 預期：餘額只動「債的幣別」，實付金額只是紀錄

## D. 身分與救援

1. 帳號頁 → 綁定 Email → 收 6 位數驗證碼 → 完成
2. 預期：身分編號**不變**（畫面最下方會顯示前 8 碼）

## E. 邀請朋友

1. 成員頁 → 產生邀請碼
2. 另一台裝置／無痕視窗輸入邀請碼加入
3. 預期：新成員看得到群組與所有帳目
